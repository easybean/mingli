# 《在职，但越来越想离开》内容地图（0.2.0）

入口：`job_exit`；定义：`employed_want_leave`；主角始终是用户，开局职业阶段为 `employed`。

固定人物只有四位：许衡（直属领导，现岗位决策）、沈放（猎头，外部机会）、唐微（即将离职的核心同事，交接与推荐）、梁澄（共同生活的家人，现实支持）。人物不承担“贵人”或反派功能，分别只提供其现实位置能够提供的信息、资源和边界。

| 幕 | 节点 | 事实重点 |
| --- | --- | --- |
| 1 | EL01–EL03 | 加责不晋升、猎头联系、核心同事离职 |
| 2 | EL04–EL06 | 晋升条件、外部 JD、同事引荐 |
| 3 | EL07–EL09 | 副线合规、家人反对裸辞、比较清单 |
| 4 | EL10–EL12 | 负荷代价、内部转岗、空缺加码 |
| 5 | EL13–EL15 | 复盘落空、面试冲突、离开叙事 |
| 6 | EL16–EL18 | 现岗与副线碰撞、奖金未落袋、内部选择 |
| 7 | EL19–EL21 | 有条件留下、内部换位、跳槽/延后/离职落点 |

六个结局：`ending_conditional_stay`、`ending_internal_move`、`ending_safe_switch`、`ending_delay_leave`、`ending_side_probe`、`ending_exit_reset`。每个结局提供标题、核心、所得、代价、质量变体、下一步行动和 `shareKey`，后者可作为结果分享文案的稳定结构化键。

## 事实与命理边界

- `astro:fusion:M01–M12` 仅参与同幕候选排序及三层依据展示；不创建 Offer、奖金或离职事实。
- `requiresAnyFlags` 和 `careerStages: ['employed']` 是硬门槛。接受新 Offer 后，用户在原公司的交接完成前仍属于在职状态，因此第七幕可继续使用 `employed`；正文只写交接、日期与书面条件，不会倒退为“仍在等待原岗位晋升”。
- 每个选择都写入含 `consumeBy` 的延迟标记；它们在后续节点的事实门槛、正文语境或结局质量中被消费。特别是 `new_offer_accepted` 只在书面 Offer 路径产生，不会与“仍在等原岗位晋升”混写。

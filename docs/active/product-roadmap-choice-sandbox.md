# Mingli 产品总规划：命盘驱动的人生选择沙盘

最后更新：2026-08-14
状态：产品方向基线，进入内容设计阶段
适用范围：H5 首轮改版、第一季「工作岔路」、后续主题扩展

> 本文替代旧规划中的产品主路径判断。旧文档关于排盘、命理信号、题库打分、前端架构和 `lifeState` 的技术事实继续有效；“今日打卡 + 五个时间尺度 + 泛人生游戏”不再作为新版首要体验。

## 1. 执行结论

Mingli 不再以“每日命理”“人格报告”“AI 算命问答”或“大而全排盘工具”为产品中心。

新版定位：

> **命盘驱动的人生选择沙盘。**
>
> 同一张命盘，不同的选择，会把人生推向哪里？

最高产品原则：

> **命盘决定局，选择决定走法。无盘不成局，不能把命理降成一层文案皮肤。**

第一阶段只做一个领域，但把它做成完整内容产品：

> **第一季：工作岔路**

用户不是来回答抽象人生题，而是带着一个正在发生的工作困境，进入一段 7—9 个关键抉择组成的连续故事。命盘提供初始条件和事件权重，用户选择改变后续局面，最终形成一条可解释、可重走、可分享的职业路线。

产品不承诺预测现实结果，不替用户作重大决定。它提供的是低风险的选择预演：让用户提前看见每种走法可能换来什么、消耗什么，以及自己反复使用了什么策略。

第一季虽然围绕工作选择展开，但每一局的起始矛盾、事件优先级、关键人物、阶段压力和结果解释，都必须能够追溯到八字、紫微斗数或当前运限信号。用户选择可以改变生活路线，但不能绕过命盘单独生成一套通用故事。

## 2. 为什么选择这个方向

### 2.1 保留现有项目真正有价值的部分

现有系统已经具备：

- 八字与紫微排盘；
- 本命与运限信号；
- 命盘触发题库；
- 选择记录；
- 压力、机会、关系、稳定、资源、身心六维状态；
- 选择回顾和路线总结雏形。

这些能力适合成为“人生沙盘”的底层，不适合继续堆成资料页。

### 2.2 放弃已被证明薄弱的假设

新版不再依赖以下假设：

- 用户愿意每天回来做一道命理题；
- 用户愿意为静态长报告付费；
- “真实的我 / 别人眼中的我”可以由命盘可靠证明；
- 好友愿意提交对用户的真实评价；
- 泛用 AI 问答可以与豆包等通用产品正面竞争；
- 功能越多，产品越容易留住用户。

### 2.3 新版的差异化组合

Mingli 的差异不来自单一技术，而来自三层组合：

1. **这是我的局**：生辰命盘让事件选择具有个人相关性。
2. **这是我的走法**：连续选择实际改变后续内容，而不是看完一段报告。
3. **这是我的路线**：结局解释先天倾向与这一轮选择之间的关系。

## 3. 产品边界

### 3.1 Mingli 是什么

- 带命理背景的互动叙事产品；
- 面向现实困境的选择沙盘；
- 可以重走不同路线的轻量人生模拟；
- 后期可延伸为决策陪练，但不是权威顾问。

### 3.2 Mingli 不是什么

- 不是真实未来预测器；
- 不是心理诊断或人格测验；
- 不是职业咨询、医疗、法律或投资建议；
- 不是命理师工作台；
- 不是需要每天打卡的习惯工具；
- 不是先堆账号、社区和付费墙的平台。

### 3.3 对外表达红线

可以说：

- “根据命盘结构生成更贴近你的情境”；
- “看看不同选择可能带来的连锁变化”；
- “这条路线反映了你这一轮的选择倾向”；
- “仅供选择预演与互动娱乐参考”。

不能说：

- “这就是你真实的命运”；
- “选择 A 一定升职，选择 B 一定失败”；
- “付费解锁改命方案”；
- “命盘证明你必须辞职 / 分手 / 投资”；
- “保证准确、趋吉避凶、消灾转运”。

## 4. 目标用户与进入时刻

### 4.1 首批目标用户

- 22—40 岁；
- 正处于工作变化期；
- 对命理、心理内容或人生模拟至少有一种兴趣；
- 不一定相信命理，但愿意用它作为观察和谈论自己的框架；
- 正在纠结，却不想读长篇理论或接受说教。

### 4.2 用户不是因为“想玩游戏”而来

典型进入时刻：

- “现在这份工作还要不要继续？”
- “失业两个月了，要不要先接受降薪 Offer？”
- “我适不适合转行？”
- “领导给我加责任但不加钱，要不要接？”
- “稳定工作和创业机会，应该选哪个？”
- “工作已经影响健康，还要不要硬撑？”

获客内容必须围绕具体问题，而不是宣传“来玩人生游戏”。

## 5. 新版核心循环

```text
看到一个具体困境
  → 选择自己当前的工作状态
  → 填写生辰信息生成初始局面
  → 进入连续 7—9 个关键抉择
  → 选择产生即时与延迟后果
  → 得到一条职业路线结局
  → 重走另一条路线 / 分享同题挑战
  → 后期可带一个现实行动回来续章
```

### 5.1 首次体验必须满足

- 不注册也能开始；
- 先选困境，再填出生信息；
- 出生信息旁说明用途和隐私原则；
- 进入后 30 秒内看到第一个具体冲突；
- 单局控制在 8—12 分钟；
- 第一局结束前不弹付费；
- 结果页必须能重走和分享；
- 分享内容不包含出生时间、地点等隐私。

## 6. 第一季：工作岔路

### 6.1 第一季的八个入口

| ID | 用户处境 | 核心冲突 |
| --- | --- | --- |
| `job_exit` | 在职，但越来越想离开 | 稳定与成长 |
| `job_lost` | 刚失业或空窗较久 | 现金流与方向 |
| `offer_choice` | 有一个或多个 Offer | 确定性与潜力 |
| `career_switch` | 想转行 | 旧积累与新起点 |
| `career_stuck` | 工作稳定但长期停滞 | 安全感与机会成本 |
| `promotion_load` | 被提拔或被加担子 | 权责、回报与消耗 |
| `side_business` | 想做副业或创业 | 试水、承诺与风险 |
| `health_boundary` | 工作影响身心或家庭 | 责任与止损 |

用户首轮只选最接近的一项，不需要输入长篇真实经历。

### 6.2 单局叙事节奏

每局由七个功能段组成，不要求每局使用完全相同的节点：

1. **局面落地**：明确现金、时间、责任或关系约束。
2. **第一次表态**：用户选择接、拒、谈条件、等待或试水。
3. **即时回响**：让选择立刻改变一件具体事情。
4. **代价显形**：前一选择的隐性成本开始出现。
5. **外部变量**：Offer、家人、同事、健康、市场或意外介入。
6. **关键决断**：出现不可两全的选择，不设置明显正确答案。
7. **路线落点**：呈现得到的筹码、承担的代价和下一步窗口。

### 6.3 第一季反复出现的人物角色

人物不是装饰，要承担事件连续性：

- **直属领导**：责任、权力、承诺和边界；
- **同事 / 合作伙伴**：支持、竞争、信息和人情债；
- **招聘方 / 猎头**：机会、包装、议价和不确定性；
- **前同事 / 老朋友**：新项目、旧信任和潜在风险；
- **伴侣 / 家人**：现金流、安全感、城市和生活代价；
- **行业前辈**：信息、判断框架和资源，不充当万能导师；
- **用户自己**：通过身体、睡眠、拖延、兴奋和后悔表现内在成本。

一局只选择 3—4 个角色进入，避免人物过载。

### 6.4 第一季事件池

事件至少覆盖：

- 降薪 Offer；
- 空窗期延长；
- 存款安全线；
- 模糊的晋升承诺；
- 加责不加薪；
- 老同事创业邀请；
- 异地机会；
- 转行培训投入；
- 简历空窗解释；
- 试用期不确定性；
- 团队重组；
- 领导挽留；
- 家庭反对；
- 伴侣支持但担忧；
- 身体报警；
- 自由职业第一单；
- 客户拖款；
- 副业与主业冲突；
- 行业下行；
- 意外的贵人引荐；
- 旧项目成果被看见；
- 接受短期过渡；
- 主动休整；
- 谈条件失败；
- 谈条件成功但责任升级；
- 错过机会后的第二窗口。

### 6.5 第一季路线结局

结局不是成功或失败评级，而是“当前路线 + 得失 + 下一窗口”。首批规划 12 类：

| 路线 | 核心含义 |
| --- | --- |
| 稳住阵地 | 先恢复确定性，换取后续选择空间 |
| 带条件留下 | 不盲走，也不无条件承担 |
| 内部换轨 | 利用旧平台完成角色转向 |
| 低谷复位 | 先修复现金流和身心，再重新出发 |
| 专业深耕 | 放弃短期热闹，积累可迁移能力 |
| 机会跳跃 | 接受波动，换取更大的成长窗口 |
| 转行试航 | 用小成本验证新方向，而非一次清零 |
| 双线过渡 | 主业保底，副线逐渐建立筹码 |
| 独立接单 | 用专业能力换取自主，同时承担不稳定 |
| 创业试水 | 先验证客户和合作，不直接押上全部资源 |
| 主动休整 | 暂停不是退出，而是恢复判断能力 |
| 及时止损 | 结束持续消耗，接受短期不确定性 |

同一路线可以有不同质量，不用继续增加大量结局名称。例如“带条件留下”可能谈到了明确回报，也可能只是争取到三个月观察期。

## 7. 分支设计：丰富但可维护

### 7.1 不采用无限分叉树

如果每个节点都永久分成三条独立故事，七次选择就会产生 2187 条路径，内容不可维护。

采用“分叉—记账—变体—汇流”：

```text
共同事件
  ├─ 选择 A → 立即后果 A + 延迟标记 A
  ├─ 选择 B → 立即后果 B + 延迟标记 B
  └─ 选择 C → 立即后果 C + 延迟标记 C
                    ↓
              进入下一公共压力点
                    ↓
       根据历史标记改变人物、措辞、可用选项和后果
```

### 7.2 每个选择记录四层影响

1. **即时后果**：本关马上发生什么；
2. **延迟标记**：两三关后触发什么；
3. **关系标记**：谁更信任、警惕、依赖或疏远用户；
4. **路线倾向**：稳定、试水、议价、突围、止损等行为策略累计。

### 7.3 选项必须满足

- 是具体动作，不是人格形容词；
- 三个选项都有人会真心选择；
- 没有一个选项同时获得所有收益；
- 不在选择前完整公布结果；
- 可以提示主要风险，但保留延迟后果；
- 不重复固定的“主动 / 稳健 / 修复”三件套；
- 允许谈条件、延迟、小步试验、求证、求助等中间策略；
- 必须与当前局面中的资源限制一致。

## 8. 命盘与后天选择怎样结合

### 8.0 不可退让的系统原则

新版由两个引擎共同工作，缺一不可：

```text
八字 + 紫微斗数 + 当前运限
  → 决定这一局为什么出现、先出现什么、哪些矛盾更重

用户连续选择 + 已产生的后果标记
  → 决定事情接下来怎样发展、进入哪条路线
```

命盘不是只在开头生成一句画像，也不是在结局补一句解释。它必须真实参与选题、排序、分支变体和结果解读。

如果排盘失败或命理信号不足，系统不能伪装成已经完成个性化推演。只能提示重新核对出生信息，或进入明确标注的“示例体验”。

### 8.1 命盘只负责四件事

1. 决定更容易抽到哪些冲突主题；
2. 调整初始筹码和敏感点；
3. 决定运限阶段优先激活哪些外部变量；
4. 在结局中提供“命盘惯性 vs 本轮走法”的对照。

命盘不直接替用户选答案，也不锁死结局。

### 8.2 三层命理输入

每一局至少同时考虑三层输入：

1. **八字底层结构**
   - 日主与月令；
   - 十神分布和主导十神；
   - 调候与喜用方向；
   - 大运、流年的干支和十神信号。
2. **紫微人生领域**
   - 命宫与身宫的行动底色；
   - 官禄宫的职业结构；
   - 财帛宫的资源与回报方式；
   - 迁移宫的外部机会与环境变化；
   - 福德宫的承压、恢复和内在消耗；
   - 相关主星、辅星与四化。
3. **当前阶段信号**
   - 当前大运；
   - 当前流年、流月；
   - 流宫叠本命后的重点宫位；
   - 当前被激活的四化与本命星曜。

三层的职责不同：八字提供结构倾向，紫微确定人生领域与角色关系，运限决定此刻什么问题更容易浮到前台。

### 8.3 命盘怎样进入一条工作剧情

以“失业后收到降薪 Offer”为例，系统不能因为用户选择了 `job_lost` 就给所有人相同故事。

命盘需要影响：

- **是否优先出现这张卡**：官禄、财帛、迁移相关信号是否正在被激活；
- **矛盾重点**：更偏现金安全、权责不对等、环境变化、专业价值还是身心消耗；
- **关键人物**：机会更可能由招聘方、前同事、旧领导、合作伙伴或家人推动；
- **可用选项**：有资源支持的人可以等待，资源紧张的人更现实的选项可能是短期承接或谈过渡方案；
- **后果语气**：同样接受 Offer，有人得到稳定但错过迁移窗口，有人则借稳定完成后续转行准备；
- **结果解释**：说明哪些来自先天结构，哪些是本轮选择累积出来的。

命盘影响的是局面权重和后果条件，不是用一句“你命中适合某工作”替代推演。

### 8.4 后天选择是实际游戏数据

后天部分不通过额外人格问卷获得，而由用户在故事中的实际选择累计：

- 是否反复争取主导权；
- 是否优先保护现金和稳定；
- 是否愿意求助、合作或谈条件；
- 是否倾向立即止损；
- 是否用小实验替代一次性豪赌；
- 是否持续以身心换取机会。

单次选择不定义用户。至少累计 3—5 次同类信号后，才在结果中使用“这一轮你更偏向……”的表达。

### 8.5 结局解释结构

```text
你的路线是什么
  → 你连续做了哪些关键选择
  → 这些选择换来了什么
  → 哪一项代价正在累积
  → 命盘底色更偏什么
  → 这一轮是在顺着惯性还是突破惯性
  → 如果现实中也面对这件事，可以先验证哪一步
```

### 8.6 用户必须看得见命盘为什么参与

不能只在后台声称“已经个性化”。每一局至少提供三个可见依据：

- 开局一句：“这段时间为什么更容易浮出工作议题”；
- 关键节点一个可展开的“为什么出现这个局”；
- 结局中的“命盘底色 vs 本轮走法”。

依据必须写成人能理解的话，同时允许展开查看对应的宫位、星曜、十神或运限。默认不堆术语，用户想追根时必须有据可查。

### 8.7 命盘驱动验收标准

每轮实现必须通过四类对照：

1. **同一问题、不同命盘**：首批事件、矛盾重点或关键人物应有明显差异；
2. **同一命盘、不同时间**：当前运限变化后，优先事件和阶段提示应变化；
3. **同一命盘、不同选择**：后续节点、人物关系和结局路线应变化；
4. **相同选择、不同底盘**：不能永远得到完全相同的后果解释。

如果只是换了命盘标签，主体故事、顺序和结果完全相同，不算完成个性化。

## 9. 状态系统的产品化改造方向

现有六维 `lifeState` 暂时保留为底层兼容层，但首屏不直接展示六个抽象数字。

工作主题优先显示 3 个情境化筹码：

- **安全余量**：现金流、稳定性和可承受时间；
- **机会窗口**：曝光、岗位、成长和可选空间；
- **身心负荷**：压力、精力和恢复能力。

关系与支持作为事件条件和结局解释出现，不必始终显示成仪表盘。

后续主题可以拥有自己的三项表层筹码，但底层仍可映射到统一 `lifeState`，避免大规模重写规则。

## 10. H5 信息架构

### 10.1 未生成状态

首屏只承担一件事：让用户选择正在纠结的问题。

建议结构：

1. 品牌与一句话价值；
2. 三张最强困境入口，展开后可看全部八项；
3. 一张示例路线结果；
4. “如何生成”的简短说明；
5. 开始按钮。

不在首屏展示命盘、今日运势、装饰建议和复杂功能导航。

### 10.2 生成流程

```text
选择工作处境
  → 出生日期 / 时间 / 地点
  → 隐私和娱乐说明
  → 生成第一幕
```

不在首次流程要求手机号、账号、真实姓名、公司、工资或长篇经历。

### 10.3 游戏状态

页面一次只突出：

- 当前发生了什么；
- 涉及哪几个角色；
- 你准备怎么做；
- 选择后马上发生了什么；
- 下一幕按钮。

命盘依据、完整状态、行动日志均作为次级折叠内容。

### 10.4 结果状态

结果页必须包含：

- 路线名称；
- 三句核心总结；
- 得到的主要筹码；
- 承担的主要代价；
- 命盘惯性与本轮走法对照；
- 一个现实验证动作；
- 重走另一种选择；
- 分享同题挑战；
- 隐私说明。

## 11. 分享与自然传播

### 11.1 分享的不是命盘结论

用户分享：

> 我在“降薪 Offer 还是继续等”这道岔路里，走成了「双线过渡者」。如果是你，你会怎么选？

朋友点击后玩同一个开局，不评价原用户，也不需要知道对方出生信息。

### 11.2 分享卡不得包含

- 出生时间和地点；
- 健康、婚育、财富等敏感断言；
- “命中注定”等绝对文案；
- 诱导恐惧的结果；
- 强制好友填写信息才能让原用户看结果。

### 11.3 可传播的三个内容单位

- **困境卡**：一个让人想代入的工作选择；
- **路线卡**：这一局走成了什么；
- **平行线卡**：如果当时选了另一条路，会发生什么。

## 12. 内容生产系统

### 12.1 一个完整事件节点需要的字段

- 节点 ID；
- 所属工作入口；
- 叙事阶段；
- 可出现的人物；
- 前置状态与历史标记；
- 用户看到的具体情境；
- 隐藏冲突；
- 三个动作选项；
- 每个选项的即时反馈；
- 每个选项的延迟标记；
- 人物关系变化；
- 状态变化；
- 后续节点候选；
- 命盘触发信号；
- 八字依据与权重；
- 紫微宫位 / 星曜依据与权重；
- 运限依据与适用时间尺度；
- 命理依据不足时是否允许作为通用过渡节点；
- 风险标签；
- 是否允许用于分享。

### 12.2 内容质量检查

每个节点进入题库前检查：

- 情境是否具体到能想象发生；
- 三个选项是否真正不同；
- 是否存在明显“标准答案”；
- 是否提前泄露了全部后果；
- 是否和前文人物关系一致；
- 是否出现不必要的命理黑话；
- 是否把医疗、投资、法律问题写成确定建议；
- 是否对失业、贫困、年龄、性别或家庭状态进行羞辱；
- 是否有至少一个后续节点消费本关产生的标记；
- 是否值得重玩，而不是换几个词重复同一题。
- 是否至少有一个明确、可验证的强命理触发信号；
- 是否能够解释为什么这张卡更适合此盘而不是所有人；
- 是否把命理信号真实用于选题或变体，而不是只贴在结果页；
- 同一节点在不同命盘下是否有合理的冲突或后果差异。

### 12.3 内容由 Codex 持续交付的顺序

1. 主题内容圣经；
2. 入口与角色矩阵；
3. 事件链大纲；
4. 节点正文和三个选项；
5. 即时 / 延迟后果；
6. 路线结局；
7. 命盘触发映射；
8. 一致性和重复度审查；
9. 可供程序消费的数据稿；
10. 上线后的低完成节点改写。

## 13. 内容规模与里程碑

### 13.1 纵向切片：先证明一局好玩

首条剧本：

> **《失业后的第五个月》**

最低内容规模：

- 1 个主要入口：`job_lost`；
- 18—24 个事件节点；
- 每局 7 个关键选择；
- 4 个主要人物；
- 6 个初版结局；
- 重玩时至少 30% 的用户可见内容不同；
- 结果页支持重走和平行线分享。

在这条剧本没有达到完成率和重走率前，不批量扩充全部题库。

### 13.2 第一季可发布版

- 8 个工作入口；
- 60 个基础事件节点；
- 20 个延迟后果 / 人物回响节点；
- 12 类路线结局；
- 6—8 个可复用角色原型；
- 单局 7—9 个关键选择；
- 同一入口至少支持 3 次有明显差异的重走。

### 13.3 后续主题候选

只有第一季指标成立后才按顺序评估：

1. 关系去留；
2. 城市去留；
3. 副业与创业；
4. 家庭边界；
5. 财务安全与机会；
6. 人生恢复期。

不同时启动多个主题。

## 14. 数据指标与决策门槛

### 14.1 必须埋点的漏斗

- 到达落地页；
- 点击一个具体困境；
- 开始填写出生信息；
- 成功生成第一幕；
- 完成第一选择；
- 完成第 3 选择；
- 完成整局；
- 查看另一条路线；
- 点击分享 / 保存结果；
- 7 天内再次进入。

### 14.2 第一轮判断标准

至少积累 100 个成功进入第一幕的有效会话后再判断：

| 指标 | 最低继续线 | 强信号 |
| --- | ---: | ---: |
| 第一幕 → 完整结局 | 35% | 50% |
| 完成后重走 | 15% | 25% |
| 分享 / 保存结果 | 8% | 12% |
| 第 1 关 → 第 3 关 | 60% | 75% |

判断顺序：

- 第 1 关流失高：开场不够相关或出生信息成本过高；
- 第 3 关后流失高：剧情没有连续性，反馈不够具体；
- 完成但不重走：结局缺少差异，选择后果不可信；
- 重走但不分享：结果卡表达不够有身份感；
- 指标未过线：先改内容，不扩主题、不做账号、不迁小程序。

## 15. 商业化顺序

### 15.1 第一阶段不收费

先证明用户愿意完成、重走和分享。没有留存与传播时，广告和付费只会放大流失。

### 15.2 通过验证后可测试

- 免费完成一条完整路线；
- 激励广告解锁“如果当时选了另一条路”；
- 低价解锁一个完整主题故事包；
- 一次性购买去广告或扩展结局；
- 海外版采用低价完整季或一次性买断。

### 15.3 不采用

- 19.9 元静态命理报告作为主收入；
- 恐吓式付费解锁；
- “不看就错过机会 / 化解风险”的付费文案；
- 一开始就做高价订阅；
- 依赖命理师咨询抽成。

## 16. 载体路线

### 16.1 当前：H5

理由：

- 改动和测试成本最低；
- 分享链接直接；
- 不必先解决商店审核和小程序类目；
- 适合验证具体困境落地页；
- 可以快速替换故事和结果表达。

### 16.2 小程序决策门槛

同时满足后再评估：

- H5 核心完成率超过继续线；
- 重走或分享至少一项出现强信号；
- 明确平台类目、内容和广告合规路径；
- 激励广告确实是用户愿意接受的解锁方式；
- 有足够日活支撑广告收入，而不是为了广告先做小程序。

### 16.3 海外版决策门槛

- 国内 H5 已证明核心玩法；
- 英文内容不是机械翻译，而是重写职业场景；
- 产品定位为 Chinese astrology life-choice game，而非普通 fortune-telling app；
- 有能力制作达到独立游戏水准的视觉、文案和声音氛围；
- 再决定 Web、iOS、Android 或 Steam。

退出条件：证明用户不仅愿意玩，也愿意回来或解锁更多内容。

## 18. 旧功能处理原则

| 旧功能 | 新版处理 |
| --- | --- |
| 今日关卡 | 暂时隐藏主入口，题库可作为事件素材 |
| 最近一月 / 一年 / 十年 / 一生 | 不在首次体验展示，运限继续用于幕后选题 |
| 人生游戏五尺度 | 退出主路径，由主题季和连续剧本替代 |
| 命盘页 | 保留为次级依据页，不占首屏 |
| 人格画像 | 不作为核心，不再使用“真实的我” |
| 选择回顾 | 保留并升级为路线结局的重要依据 |
| 六维 lifeState | 底层保留，前台改成情境化筹码 |
| 紫灵牌 / 饰品建议 | 暂时隐藏，不投入新增工作 |
| AI 问答 | 不做 |
| 账号系统 | 验证后再做；首轮优先本机进度 |
